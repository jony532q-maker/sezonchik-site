СЕЗОНЩИК — заявки с сайта в MAX

Папка site содержит заменяемые файлы сайта и включает обновление доставки
и заказов по счёту. С пустыми настройками на странице trees.html продолжает
работать привычный сценарий выбора мессенджера. Новый сценарий включает
телефон для связи и показывает номер принятой заявки.

Подключение
1. Создайте бота в MAX для бизнеса и дождитесь модерации.
   https://dev.max.ru/docs/chatbots/bots-create/create
   Откройте личный диалог с ботом и нажмите «Начать». Получите user_id
   получателя из события bot_started. Для разовой проверки нового бота,
   у которого ещё нет вебхука, подходит тестовый GET /updates.
   https://dev.max.ru/docs-api/methods/GET/updates
2. Разместите папку server на постоянно работающем сервере в России.
   Установите requirements.txt и запустите python orders.py.
   Задайте MAX_BOT_TOKEN и MAX_USER_ID в переменных окружения сервера.
   Укажите ORDERS_DB на постоянном диске. Сервис по умолчанию слушает
   127.0.0.1:8081. Опубликуйте POST /orders и GET /health через HTTPS-прокси.
   SITE_ORIGIN по умолчанию https://sezonchik27.ru. Для платформы, которая
   проксирует порт контейнера, задайте BIND_HOST=0.0.0.0 и используйте её PORT.
   Используйте доверенные сертификаты для обращения к MAX. При необходимости
   MAX_CA_FILE указывает на PEM-файл с официальным сертификатом Минцифры.
   https://dev.max.ru/docs-api/
3. В trees.html укажите полный HTTPS-адрес /orders в sezonchik-orders-api
   и адрес действующей политики обработки данных в sezonchik-orders-privacy.
   Опубликуйте четыре файла из папки site в корне сайта.
4. Проверьте отправку тестовой заявки с вымышленными данными. Сверьте
   один номер в браузере и в личном диалоге с ботом. Проверьте настройки
   уведомлений этого диалога на телефоне.

Заявка записывается в очередь до подтверждения клиенту. При временной
недоступности MAX отправка повторяется. После успешной доставки телефон,
имя и адрес удаляются из очереди. Для повторного запроса с тем же ID
возвращается тот же номер. В редком случае, когда MAX принял сообщение,
а ответ потерялся, возможен повтор уведомления с тем же номером.

Цена в сообщении передаётся из витрины и предназначена для проверки
продавцом. Статус оплаты определяется отдельной интеграцией с эквайрингом.
