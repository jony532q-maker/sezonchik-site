# Запуск сервера заявок СЕЗОНЩИК (после загрузки V14)

**Важно:** ZIP не разворачивает сервер и не создаёт DNS автоматически.

## Необходимые условия

- Сервер и база персональных данных граждан РФ на территории РФ.
- DNS A/AAAA-запись `orders.sezonchik27.ru` на этот сервер.
- HTTPS-сертификат (например, Caddy или Nginx + Let's Encrypt).
- Приватные переменные окружения (НЕ в репозитории):
  `MAX_BOT_TOKEN`, `MAX_USER_ID`, `SITE_ORIGIN=https://sezonchik27.ru`,
  `ORDERS_DB=/var/lib/sezonchik/orders.sqlite3`, `ORDERS_ENABLED=0`.
- Установленная Python-среда с `aiohttp`.

## Пример конфигурации обратного прокси Caddy

```
orders.sezonchik27.ru {
    reverse_proxy 127.0.0.1:8081
}
```

Запуск Python-сервиса должен быть организован через systemd или аналогичный процесс-менеджер, с ограниченными правами, резервным копированием и защитой доступа к базе.

## Безопасный порядок включения

1. Установить серверные зависимости и запустить `server/orders.py` с `ORDERS_ENABLED=0`.
2. Проверить `https://orders.sezonchik27.ru/health` — ответ `OK`.
3. Проверить `https://orders.sezonchik27.ru/config` — `enabled: false`.
4. Проверить доставку уведомлений через MAX, хранение данных, защиту и актуальность политики.
5. Установить `ORDERS_ENABLED=1`, перезапустить процесс.
6. Проверить `/config` — `enabled: true`, `privacy_url` должен указывать на сайт.
7. Сделать тестовую заявку через форму и убедиться, что магазин получил её в MAX.
8. Зарегистрировать в Метрике цель `v9_booking_request` (срабатывает только после подтверждения API).

Для посетителя до пункта 6 сохраняется сценарий через мессенджеры.

## Запреты

Нельзя публиковать `MAX_BOT_TOKEN`, SQLite-базу с заявками и иные секреты в GitHub. Нельзя включать прямые заявки до проверки законного хранения персональных данных.
